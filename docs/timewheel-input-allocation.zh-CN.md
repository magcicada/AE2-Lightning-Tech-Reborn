# LT 时间轮 CPU 的动态输入分配

## 范围与兼容

分配器位于 LT 的 `crafting.timewheel.allocation` 包，仅由 LT 时间轮 CPU 使用。
不修改 Thunderbolt 源码或公共接口，不给原版 AE2、AdvancedAE 或 NeoECO 的 CPU 安装分配器。
`ICraftingPlan`、planner、样板定义和提供器查找保持原语义。

LT 接单时从原始 `patternTimes()` 和展开后的 loop 任务建立执行任务表，不把可选的
`PlannedInputAssignments` 固化为选料限制。配套 TB 已停止自动生成这份固定绑定；原计划保留
注册样板身份与总需求，具体选料由 CPU 根据现货和剩余任务确定。
旧存档的 `#plannedInputs` 继续校验和读取，但在 LT 内解除 `PlannedInputPattern` 包装，
相同原样板的剩余次数合并；loop 的消费者身份、种子和路由包装保留。
分配状态不写入 NBT，每次接单或加载后根据任务表和实际库存重建。

三条取料路径都经过分配：单次、普通多次投递和批量提供器投递。
前两条使用 LT 的 `TimeWheelInputExtractor`。批量路径继续调用原有 `BatchExecutor`，
保留其提供器筛选、调度、能量、成功次数、共享输入、拒收与剩余量处理。
LT 通过同步作用域和一个 Mixin 只替换当前 LT 任务的取料调用；必须同时匹配样板对象和
库存对象，其他 CPU 或重入的不同任务原样调用 Thunderbolt。作用域在 `finally` 中恢复或清除。

批量结果按原生格式传回派发器，构造器查找仅执行一次，保留具体返还物和共享输入信息。
如果依赖的结果格式不兼容，则停止这条批量快路，交给 LT 自身的普通投递路径；转换失败会
先回滚已取材料。不会改用未经分配约束的批量取料。

## 有限材料与交集

需求节点为“样板 + 输入槽位”，有限消耗量取剩余次数乘输入倍率。
候选 key 必须通过原输入的 `isValid`，库存和提取始终使用完整 `AEKey`。
精确需求与模糊需求共享同一份物理容量，不永久把一个 key 归入某种匹配类型。

示例：库存普通玻璃 G、石英玻璃 Q 各一份，任务为 `{G,Q} → X` 和 `X + Q → 成品`。
分配器为前者选 G，为后者保留 Q。若 Q 有多余库存，前者仍可使用不影响剩余任务的部分。
两个模糊集合相交时，分配器维护联合可行性，不能把各 key 独立算出的最大可用量同时放开。

key 按“接受它的实际槽位及单位量”组成容量桶，仅创建实际存在的签名，不枚举集合子集。
每个具体 key 不足一个模板单位的零头先舍去，不能拼成另一个 key 的整份输入。
桶上的稀疏匹配证明可沿替代路径调整，保持选料自由；批量放大经过联合试取。

成功取料后保存的证明适用于取料前的数量，不提前认定提供器已接受。
全拒收和部分接受都按实际 key 回库，任务计数仅在实际成功后变化。
后续以真实库存和任务通知修正证明，过期模拟不能覆盖新状态。

## loop 的独立种子保护

未来产量不能作为现货。可能补产的槽位不把整单生命周期需求全部锁在现有库存中。
LT 的消费者种子账本先生成实际可见库存，分配器再在该视图上取料。
`ExecuteLoopPattern.isInputSeedSlot` 指明已经独立保护的槽位：其他任务求解时不重复为它
预留一次，选中该槽位时仍必须具备本次实际需要的材料。同一 loop 的普通消耗槽位继续保护。

这避免以下等待环：loop 的最后一个生产成员已经发配，B 被种子账本留给下一个成员；
该成员还需要普通配方生产 X，而普通配方接受 `{B,G}`。若再要求公共库存为 loop 留 B，
即使 G 已就绪也会阻断普通配方。独立保护标记避免这种二次保留，同时不允许普通任务偷走 B。

动态组件/耐久变体按实际到货认领种子份额。过载输出的种子额度由原生认领队列分配，
不能在模拟机输出时提前指定“哪一件物理产物属于种子”。

## 缓存、复杂度与边界

提供器能力与执行输入分配使用不同缓存。NeoECO 解析器显式允许配套 TB 跨 tick
复用能力包装和不支持的结果；`beginDispatchTick` 仅重置
上个 tick 的普通投递降级。容量和机器状态仍实时读取。提供器/样板列表变更由 TB 的
修订号失效缓存，具体输入分配仍按下列实际库存通知维护。

- 每个 job 一个分配器，按主身份索引潜在相关槽位；`dropSecondary()` 仅用于候选查找。
- 已知 key 变化记录到有界待处理集合，重复事件合并，不重新查询全部配方。
- 数量通知与次数通知都齐全、且库存是原生可通知视图时，增量维护可行分配。
  动态保留视图仍重新读取实际可见数量，不能缓存会变化的种子保护额度。
- 桶内只索引可提供完整模板单位的 key，分配边只保留正额度。耗尽的节点及时移除，
  不反复扫描零库存前缀；新出现的组件 key 归零后移出非锚点缓存。
- 热路径复用已证明的额度及正库存索引，单项查找/消费通常为预期 O(1)。新候选发现、
  替代链和初始联合求解依赖真实相关图规模，不承诺任意交集都能均摊 O(1) 或 O(log n)。
  一个 key 的直接接受槽位少，也不能排除长度任意的替代链。
- 缺料失败按变化版本缓存，到货和剩余次数变化会使其失效。
- 匹配只遍历实际关系，单 tick 搜索工作量有界；大图未算完会继续等待，不会因预算耗尽放开保护。
  默认关系上限 32768，`ae2lt.executionAllocationMaxPairs` 可调整至硬上限 262144；
  每族候选和待处理变化各上限 4096，查询快照最多 8 份。

这是执行时的材料仲裁，不是任意生产依赖图的死锁证明器。不兼容的替代单位量继续保留原
取料语义；实际服务器 TPS、堆占用和长期运行需要运行环境验证。

## 回归覆盖

有限精确/模糊交集、穷举小域 oracle、替代链、重复槽位物理容量、部分拒收、共享工具、
流体零头、迟到组件/耐久变体、缓存归零回收及热路径访问量均有测试。
loop 测试包含 180 组调度与一个关闭独立保护的死锁对照：普通配方争中间产物、两个 loop、
共享种子边界、精确与模糊竞争，以及随机分批返回、拒收重试和不同初始发配顺序。
测试驱动使用实际账本、过载认领、库存保护和取料代码；不等价于完整 Minecraft 世界压测。
批量桥接另验证作用域隔离/异常清理、原生结果的部分回滚及返还物记账，以及依赖中的目标调用点。
